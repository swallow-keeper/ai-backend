# 상태, 결과, 사유 코드

이 문구는 초안입니다. 화면 문구의 최종 결정은 팀이 합니다. "흡인이 의심돼요", "안전"처럼 단정하는 표현은 쓰지 않습니다.

앱 첫 화면, 결과, 기록에는 진단이 아니라는 점을 둡니다. 초록에 해당하는 화면에도 흡인이 없다는 뜻이 아니라는 문장을 같이 둡니다.

## 세션 단계

`TRACKING` 감시 중.

`CANDIDATE` 삼킴 후보를 방금 받음.

`AWAITING_VOICE` 발성 대기. 제한 시간 기본 10초.

`ANALYZING` 업로드된 클립 분석 중.

`RESULT` 결과를 방금 확정. 곧 `TRACKING`으로 돌아갑니다.

`RECHECK` 기침 후 다시 발성하라는 안내. 음성 업로드를 한 번 더 받습니다.

`ALERT` 주의. 경고 표시.

`AWAITING_RESOLVE` "처치를 완료했어요" 대기.

발성 대기 중 같은 삼킴으로 보이는 추가 후보는 새 요청으로 만들지 않고 합칩니다. 연결이 끊겼다가 붙으면 `RESYNC`로 마지막 단계를 다시 보냅니다.

재녹음은 최대 2회입니다. 그 이후 실패는 건너뜀으로 기록합니다.

τ1, τ2, K는 `registry/model_registry.yaml`의 가설값입니다. 흡인 민감도로 정하지 않습니다.

## 사유 코드

실패로 분석을 멈추는 코드:

- `VOICED_TOO_SHORT`: 유성 구간이 하한보다 짧음
- `TOO_QUIET`: 음량이 너무 작음
- `CLIPPING`: 잘린 샘플 비율이 큼
- `LOW_SNR`: 소음 대비 신호가 작음
- `NOT_SUSTAINED_VOWEL`: 말하기, 기침, 헛기침, 발성 실패로 판단
- `DECODE_FAILED`: WAV로 읽지 못함
- `TOO_LONG`: 디코드 길이가 상한을 넘음
- `TOO_LARGE`: 파일 크기가 상한을 넘음

분석은 하되 기준을 다시 받으라고 알리는 코드:

- `LEVEL_SHIFT`: 입력 레벨이 기준과 많이 다름
- `NOISE_FLOOR_SHIFT`: 소음 바닥이 기준과 많이 다름

기준 등록:

- `BASELINE_TOO_FEW`: 품질을 통과한 클립이 2개 미만
- `BASELINE_UNSTABLE`: 클립 사이 산포가 큼

기타:

- `CONSENT_REQUIRED`: 음성 분석 동의가 없음
- `WRONG_PHASE`: 현재 단계에서 허용되지 않음
- `NOT_IMPLEMENTED`: 2차 기능
